# 《清台》设计摘要

本文件是公开仓库里的设计说明。完整规格（词库 40 词全文、九关摆位坐标与杆数预算、`tuning.ts` 调参总表、14 条观察规则原文）不在这里，等作品正式发布后再公开。

| 项 | 内容 |
|----|------|
| 作品名 | 清台（暂定；备选：打进去了 / 今晚这一局） |
| 一句话定位 | 把情绪打进袋里的竖屏台球解压游戏 |
| 赛道 | Qoder 高校创造力大赛 · LifeHack 生活娱乐 |
| 形态 | 纯前端 Web App，无后端、无登录、无外部数据请求 |
| 单次时长 | 一关 45–60 秒完成一次情绪闭环；主线 3 章 9 关约 8–10 分钟 |
| 目标用户 | 高校学生与毕业 5 年内的工作者，18–30 岁，主要在微信内浏览器打开 |

---

## 1. 核心主张

情绪疏导类产品普遍走"表达—被倾听"路径（日记、树洞、AI 陪伴），要求用户主动组织语言，摩擦高。而人在焦虑、憋屈时的真实需求往往不是"说出来"，是"先把这口气出了"。

台球（弹弓射击类）是移动端反馈密度最高的休闲玩法之一：瞄准、出杆、撞库、进袋四个环节各带一次独立感官奖励，单次循环 4–6 秒。把"情绪具象化成球 → 物理销毁"和它绑定，就能在不要求用户表达的前提下完成一次低门槛的情绪释放。

**关键设计主张：情绪不是贴在球上的标签，而是驱动物理规则的参数。** 这是本作与"换皮台球"的分界线。

| 对比 | 它们的做法 | 本作的做法 |
|------|------------|------------|
| 换皮解压小游戏（捏泡泡、切肥皂） | 无意义物理破坏 | 破坏对象由玩家赋予意义（词） |
| 情绪日记 / 树洞 | 要求用户表达 | 零表达，只需操作 |
| 弹弓射击类关卡游戏 | 关卡是障碍排列 | 关卡是处境（凌晨两点 / 家庭群里 / 答辩前夜） |
| 台球模拟游戏 | 追求真实规则 | 追求手感 + 情绪隐喻，规则服务于表达 |

## 2. 三条可验证的核心体验

| # | 体验目标 | 验证方式 |
|---|----------|----------|
| CE-1 | 出杆这一下本身就很爽，与主题无关 | 真机盲测连续 20 杆无放弃 |
| CE-2 | "某些情绪不能用砸的"是身体先懂，不是读到文案懂 | 观察玩家对「焦虑」的力度分布是否自发下降 |
| CE-3 | 结算反馈描述"你刚才做了什么"，而不是"你应该怎么想" | 反馈文案 100% 由本局行为数据驱动，无随机文案池 |

## 3. 球类机制

七种球类在 V1 落地，每一种的物理差异都是那层隐喻本身：

| 类型 | 名称 | 物理差异 | 隐喻 |
|------|------|----------|------|
| `NORMAL` | 普通球 | 无 | — |
| `ANGER` | 愤怒 | 恢复系数 > 1，越撞越弹，有疲劳衰减 | 砸得越狠反弹越多 |
| `SOCIAL` | 社死 | 首次进袋弹回一次，第二次才销毁 | 想装作没发生 |
| `ANXIETY` | 焦虑 | 持续抖动 + 袋口斥力；轻推时斥力严格为 0 | 越用力追它越躲 |
| `SELF_CRITIC` | 自我批评 | 进袋不消失，碎成两片，碎片可独立进袋 | 骂完还有回音 |
| `DARK` | 未点亮 | 需撞击两次才可见可进 | 还没被看清的部分 |
| `WANDERER` | 游荡 | 自主低速随机运动 | 不肯停下来的念头 |

`PROCRAST`（拖延）、`CONSUME`（内耗，需成对距离约束求解）明确排到 V2。

**约束**：特化只影响"力"与"进袋判定"，绝不修改碰撞解算本身——手感优先于隐喻。

## 4. 关卡与结构

- 3 章 × 3 关 = 9 关。章一约 2 分钟独立成篇：只玩章一也能拿到一次完整疏导反馈。
- 三章的情绪层次：章一具体、好笑、不疼（早八 / DDL / 绩点这一类）；章二往内一层（委屈 / 憋屈 / 家庭群）；章三最疼的那批（自我批评类全部为 `SELF_CRITIC`）。
- 章与章的视觉差别由**灯光**承担，台呢全游戏只用一种绿。
- 选关页九关全开放，不强制顺序、不加锁——`localStorage` 在微信里可能被清空，强制顺序会让用户永远卡在打不开的状态。

## 5. 失败的定义

**不存在"失败"这个状态。** 杆数用完不判负，给 3 杆续杆，可反复使用；母球落袋复位且不扣杆数。无扣分、无星级、无"你真差"式反馈。

## 6. 疏导反馈

每章结束后一张疏导页，三段：复述（本局做了什么）→ 观察（数据驱动，每页只有一句）→ 一件小事。文案全部由 `RunStats` 采集的真实行为推导，不从随机池里抽。

## 7. 伦理与安全红线

| # | 红线 | 落实方式 |
|---|------|----------|
| 1 | 不做诊断、不提治疗建议、不假装是心理咨询 | 全局不出现"症状""治疗""干预""抑郁症""焦虑症"；反馈页底部固定免责说明 |
| 2 | 不生成自伤、自杀相关意象 | 词库硬过滤，不出现身体/外貌羞辱词，不出现人称靶子 |
| 3 | 不惩罚玩家 | 无失败态、无扣分、无星级 |
| 4 | 不替用户定义情绪 | 观察句只描述动作与力度，不推断"你是不是很难过" |
| 5 | 不制造依赖机制 | 无签到、无体力、无每日任务、无推送、无广告、无内购 |
| 6 | 求助通道必须显眼 | 每张疏导页与结算卡固定一行求助提示 |
| 7 | 不采集、不上传任何数据 | 无埋点上报、无网络请求（除静态资源），统计数据只存本地 |

> 上线前待核对：求助热线号码的准确性，以及它在 4 个出口（三张疏导页 + 结算卡）都不被遮挡。

## 8. 为什么是纯前端

这不是巧合，是一次明确的代价交换。项目的全部已知平台风险——认证 all-or-nothing、private 模式网关拦截、产物体积上限、无自定义域名、数据库 schema 冲突、Function 冷启动——都由"纯前端、零后端、零外部请求"这一条决策一次性清零。换来的约束是包体必须 < 250 KB、不加载任何 webfont、分享降级为保存图片。

## 9. 明确不做

账号体系、排行榜、好友对战、实时联机、LLM 调用、语音输入、心理测评、应用内购买、广告、横屏适配、英文版本、球的旋转（English/塞）与母球走位控制。
